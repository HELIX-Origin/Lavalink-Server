# ⚙️ Configuration Reference

This page documents the complete configuration schema used in `application.yml` and its corresponding environment variables.

---

## 🔐 Environment Variables vs Client Settings

It is critical to distinguish between **Lavalink Server Variables** and **Discord Bot Client Variables**:

| Variable Type | Examples | Where It Is Configured | Purpose |
| :--- | :--- | :--- | :--- |
| **Server Variable** | `PORT`, `LAVA_PASS`, `YOUTUBE_CIPHER_URL`, `SPOTIFY_CLIENT_ID` | Lavalink Server (`render.yaml`, `app.json`, `.env`) | Tells Lavalink what port to bind to, what password to demand, and which external APIs to query. |
| **Bot Client Variable** | `LAVA_ENABLED`, `LAVA_EXTERNAL`, `LAVA_HOST`, `LAVA_SECURE` | Discord Bot (`Master-Bot` `.env`) | Tells your Discord bot how to reach this external Lavalink server. **Never configured on the Lavalink server.** |

---

## 📋 Comprehensive Server Variables

The Lavalink server resolves **Port** (`$PORT`, defaulting to `2333`) and **Domain** (`$RENDER_EXTERNAL_HOSTNAME`, `$RAILWAY_PUBLIC_DOMAIN`, `$HEROKU_APP_DEFAULT_DOMAIN_NAME`, `$FLY_APP_NAME`) directly from the cloud host environment.

The following server configuration variables are exposed and supported:

| Variable | Default Value | Description |
| :--- | :--- | :--- |
| `LAVA_PASS` | `youshallnotpass` | Authentication password for incoming WebSocket and REST API requests. |
| `YOUTUBE_REFRESH_TOKEN` | *(empty)* | YouTube OAuth 2.0 refresh token generated by `/youtube-auth`. |
| `YOUTUBE_API_KEY` | *(empty)* | Optional YouTube Data API v3 key. |
| `YOUTUBE_CIPHER_URL` | `https://cipher.kikkia.dev/` | Remote deciphering service URL for YouTube signature decryption. |
| `YOUTUBE_CIPHER_PASSWORD` | *(empty)* | Optional password for self-hosted yt-cipher (leave empty for default public endpoint). |
| `SPOTIFY_CLIENT_ID` | *(empty)* | Client ID from the [Spotify Developer Dashboard](https://developer.spotify.com/dashboard). |
| `SPOTIFY_CLIENT_SECRET` | *(empty)* | Client Secret from the Spotify Developer Dashboard. |

## 📄 `application.yml` Core Sections

### 1. Server & Networking
```yaml
server:
  port: ${PORT:${LAVA_PORT:2333}}
  address: 0.0.0.0
  undertow:
    buffer-size: 1024
    direct-buffers: true
    threads:
      io: 4
      worker: 32
```
- **`port`**: Interpolates the injected `PORT` or `LAVA_PORT`, defaulting to `2333`.
- **`address`**: Binds to `0.0.0.0` (all IPv4 interfaces), allowing external inbound traffic inside containers.
- **`undertow`**: Configures the high-performance non-blocking HTTP/WebSocket Undertow engine.

### 2. Lavalink Core & Audio Buffers
```yaml
lavalink:
  server:
    password: "${LAVA_PASS:youshallnotpass}"
    sources:
      youtube: false        # Handled by the modern YouTube Plugin
      soundcloud: true
      bandcamp: true
      vimeo: true
      nico: true
      http: false
      local: false
    filters:
      volume: true
      equalizer: true
      karaoke: true
      timescale: true
      tremolo: true
      vibrato: true
      distortion: true
      rotation: true
      channelMix: true
      lowPass: true
    bufferDurationMs: 400
    frameBufferDurationMs: 10000
    opusEncodingQuality: 10
    resamplingQuality: HIGH
    trackStuckThresholdMs: 30000
    playersTimeout: 0
```
- **`bufferDurationMs`**: Target audio packet buffer in milliseconds (400ms ensures smooth playback without stuttering).
- **`frameBufferDurationMs`**: 10000ms (10s) frame buffer prevents underruns during sudden network spikes.
- **`opusEncodingQuality`**: Max quality (10) for crystal-clear voice transmissions.
- **`playersTimeout`**: Set to `0` so players do not automatically disconnect on pause.

### 3. JVM Flags & Tuning
The Docker container starts with:
```bash
java -Xmx512M -Djdk.tls.client.protocols=TLSv1.2,TLSv1.3 -jar Lavalink.jar
```
- **`-Xmx512M`**: Restricts the maximum Java heap allocation to 512 MB, keeping total process RAM well within free cloud tier constraints (e.g. 512 MB on Render/Fly.io).
- **`-Djdk.tls.client.protocols=TLSv1.2,TLSv1.3`**: Enforces modern, secure TLS negotiation with streaming content delivery networks.
